### Non-blocking Suggestions

- `PipelineRunServiceSpec`'s two new manual-submit/preview tests point `seedTextUrlDs` at `https://example.com/notes.txt`, a real external domain. In a network-isolated CI runner this will fail closed (DNS/connect error) rather than fail via the intended "unwired-seam-in-this-test's-DI" path, but both failure modes converge on the same asserted outcome (`Left`/`UnprocessableEntity`/`status shouldBe "failed"`), so it is not currently a false-negative risk — just a latent flakiness/hygiene note if example.com ever behaves unexpectedly (e.g., returns 200) or if the CI network policy changes. Consider pointing these two tests at a source that fails for an engine-internal reason (e.g. no seam wired) rather than a live external host, for determinism independent of network conditions.
- `InProcessPipelineEngineUrlRefetchSpec.scala` is 309 lines, over the repo's 250-line soft budget (flagged by `check-scala-quality.mjs` as a soft warning only, consistent with ~40 other spec files already over budget repo-wide). Not blocking.
