That matches the CI signature exactly. In the other order (DELETE first, or UPDATE blocked behind the cascade's row lock), the UPDATE or the owner SELECT finds no row, so `won = false`, then `Missing`, then 404. Both orders give a consistent outcome. Neither is a deadlock.

Under H1 the terminal write won *before* the delete, so the correct linearization is "the run succeeded, then the pipeline was deleted", and `Right` is correct product behavior. The design's test-only classification (D1) is therefore well-founded, provided the probe confirms H1.
