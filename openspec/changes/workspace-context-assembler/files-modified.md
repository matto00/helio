## Cycle 2 (evaluation-1.md fixes)

- `schemas/workspace-context.schema.json` — **fix for evaluation-1.md change request 1**: dropped every `Option[T]` field from each `$defs` object's `required` array (`DataSourceEntry.tag`; `DataTypeEntry.sourceId`/`.tag`; `PipelineStep.validationError`; `PipelineEntry.lastRunStatus`/`.lastRunAt`/`.lastRunRowCount`/`.tag`/`.stepsError`) — spray-json's `jsonFormatN` macro omits a `None` field from the wire entirely rather than emitting `null`, so `required`-listing them made the schema reject nearly every real response. Fields stay in `properties` (still type-validated as `["T", "null"]` when present) — matches the existing `schemas/panel.schema.json` `dataAsOf` convention. Each affected field's description now explicitly documents the omit-not-null behavior.
- `backend/build.sbt` — added `com.networknt % json-schema-validator % 1.0.87` (Test scope) — a real JSON Schema 2020-12 validation engine (Jackson-based; Jackson is already pinned on the classpath) for the strengthened 4.6/4.6b tests below.
