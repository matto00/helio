# Consumer audit: the first `selectedDashboardId` on load (HEL-1624)

Derived from `grep -rlw selectedDashboardId frontend/src --include=*.ts --include=*.tsx`, test files and `src/test/` excluded (27 files),
plus `shared/session/` for HEL-1634 (it does not name the field; it resets the slice). Before = main: the first non-null value on load is the landing
default (first owned dashboard), replaced later by the deep link (DashboardRoute effect) or the saved active tab (hydrateTabs, after up to 3 s).
After = the first non-null value is the load target (deep link > saved active tab > ...), so nothing sees a dashboard that is replaced later.
