### Verdict: REFUTE

Two concrete, verifiable gaps in the planning artifacts, both found by comparing design.md/tasks.md's claims against the actual file contents rather than taking them at face value:

### Change Requests

1. **Test-split plan omits two widely-shared fixture constants.** `ChartPanel.test.tsx` has exactly four module-level symbols outside any `describe`: `renderChart`, `getOption` (design.md D6 / tasks.md 4.2 correctly moves these to `chartPanelTestHelpers.tsx`), and `baseAppearance`/`baseChartConfig` (lines 198-212), which design.md/tasks.md never mention. I grepped every use of `baseAppearance`/`baseChartConfig` and confirmed they are referenced from **all five** proposed destination files: the retained `ChartPanel.test.tsx` (pie chart §214, scatter §474, F-027 §688), `ChartPanel.appearance.test.tsx` (chartOptions HEL-248 §508), `ChartPanel.aggregate.test.tsx` (§262, §365), `ChartPanel.compact.test.tsx` (§418, §744, §818), and `ChartPanel.theme.test.tsx` (§926). Left unaddressed, the executor either discovers this mid-split via a typecheck failure (self-correcting but wasted cycles) or improvises a duplication/sharing decision the design should make explicitly. **Required revision:** add `baseAppearance`/`baseChartConfig` to tasks.md 4.2's list of items moving into `chartPanelTestHelpers.tsx` (or explicitly decide "duplicate per file" with a stated reason), so the split is exhaustively specified before execution.

2. **D2's plan to thread `theme`/`accentColor`/`themeSyncTick` into `buildChartOption` as plain arguments creates a real, unaddressed lint risk under this repo's zero-warnings policy, and is unnecessary.** `frontend/package.json`'s `lint` script runs `eslint src --max-warnings=0`; `eslint.config.cjs` spreads in `tseslint.configs.recommended.rules`, which includes `@typescript-eslint/no-unused-vars` with its default `args: "after-used"` — meaning trailing, genuinely-unused parameters ARE flagged. In the current file, `theme`/`accentColor`/`themeSyncTick` are referenced only via `void theme; void accentColor; void themeSyncTick;` (lines 363-365) specifically to satisfy `react-hooks/exhaustive-deps`'s "unnecessary dependency" check on the *hook's* `useMemo` array — that rule only inspects actual React hook calls, never a plain function like `buildChartOption`. If the executor follows D2 literally and appends these three as trailing, unused parameters to a **plain function**, `@typescript-eslint/no-unused-vars` will very plausibly flag them (no `argsIgnorePattern` is configured in `eslint.config.cjs` to except underscore-prefixed names), failing `npm run lint`. Worse, this complexity buys nothing: the red-first mutation proof's actual target for the theme-sync mechanism (tasks.md 5.2 — "drop `themeSyncTick` from the `useMemo` deps in `useChartOption.ts`") lives entirely in the *hook's* dependency array, never inside `buildChartOption`'s body — so `buildChartOption` never needs `theme`/`accentColor`/`themeSyncTick` as arguments at all, only the real, used inputs (`themeTokens` from `resolveChartTheme()`, plus the existing data/appearance/compact inputs). **Required revision:** revise D2 to drop `theme`/`accentColor`/`themeSyncTick` from `buildChartOption`'s signature entirely; keep the `void theme; void accentColor; void themeSyncTick;` cache-buster pattern (and the `resolveChartTheme()` call) inside `useChartOption.ts`'s own `useMemo` callback, exactly mirroring the current file's structure — this is both lint-safe and a more literally mechanical move, consistent with D3's own stated "direct, mechanical move" rationale.
