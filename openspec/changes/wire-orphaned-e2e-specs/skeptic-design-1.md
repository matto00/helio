### Verdict: REFUTE

### Change Requests

1. **D5's precondition is incomplete in exactly the way that lets a tautology through — it never requires the replacement control to be one the STEADY-STATE guard actually measures.** As written ("box-floored on height at mobile widths WITHOUT a width floor"), the precondition is satisfiable by an arbitrary rule anywhere in `frontend/src`. The old anchor `.panel-list__add` was surface 6's own measured anchor in `e2e/hel813-mobile-touch-target-floor.spec.ts`. A replacement that is not swept by `sweepSurface`/`assertFloor` in that spec would demonstrate that the *helper* is width-sensitive on a control **no shipped guard covers** — a demonstration disconnected from the thing it certifies, which is not "genuinely equivalent" per AC 3. Add to D5 and task 6.1: the candidate MUST be a selector currently measured by a surface in `e2e/hel813-mobile-touch-target-floor.spec.ts` at 430px via `assertFloor`/`sweepSurface` (not `assertExpanderFloor`, not `assertHiddenAtWidth`). If no such selector also satisfies the height-floor/no-width-floor condition, that is a DELETE outcome under 6.3.

2. **The precondition also omits the baseline-green requirement, so a "red" could be unattributable to the mutation.** Case B's contract is PASS(baseline) → FAIL(mutated) → PASS(reverted). Add to D5/task 6.1: the candidate must be *measured* (not reasoned about) to satisfy `assertFloor` on BOTH axes unmutated at 430px, and the measurement recorded in the report. Without this, a control with no width floor that already renders sub-44px wide would make the mutated red vacuous.

3. **Task 6.1's search mechanism is unconstrained and will structurally miss sites (standing lesson 6).** "Search `frontend/src` for a control that is box-floored on HEIGHT" invites a grep for `min-height: 44px`, which cannot see height floors reached via `height`, a `--control-*`/`--space-*` token, padding + line-height, or a shared class declared in another file. Constrain the mechanism: enumerate the steady-state spec's measured selectors and determine the property by **runtime measurement / computed style at 430px**, not by string search. Additionally state as an explicit disqualifier that a height floor inherited from a shared class or token does not qualify, because the harness's mutation would then alter other controls' rendering — the mutation must be confined to the candidate's own rule.

4. **A repaired Case B must use the epsilon-adjusted floor in its own assertions, not the bare literal.** Today Case B asserts `expect(mutatedBox.height).toBeGreaterThanOrEqual(44)` (regression spec, "Confirm RED on the width axis" block) while `assertFloor` passes at `44 - RENDERED_BOX_EPSILON_PX` (43.25). A replacement control that legitimately measures e.g. 43.6 — a documented, expected sub-pixel outcome per `RENDERED_BOX_EPSILON_PX`'s own 120-sample evidence — would make the repaired harness spuriously RED on its wrong-axis discriminator. Add to task 6.4: the height discriminator must use `DEFAULT_MIN_PX - RENDERED_BOX_EPSILON_PX`, imported, not a re-typed `44`.

5. **No task ever runs the FINAL globbed set as a single suite (standing lesson 7 — composition).** Task 1.3 runs each orphan *individually*. The glob runs them in ONE Playwright process with `fullyParallel: false`, `retries: 0`, one worker, sequentially, against a shared dev backend and a shared Postgres that accumulates registered users, dashboards, pipelines and toasts across specs. "Each of eleven passes alone" does not compose to "the suite passes". Add a task, after task 3 and task 4 and before task 7: run the exact committed glob invocation once, whole-suite, capture the aggregate transcript, and quarantine (with a ticket, per D2) anything red only in the combined run. Report the wall-clock from that run as the D3/Risks number.

6. **Task 3 must delete or rewrite the now-false comment already in `ci.yml`, not merely add a new one.** Lines 199-205 currently assert "the ONLY spec run here is the new steady-state mobile touch-target guard … The other pre-existing e2e/ specs were never CI-gated; broadening this job to cover them is a natural follow-up, not bundled into this change." After this change every clause of that is false. Task 3.2 only says *add* a comment. Given this repo's documented confidently-false-documentation trap, make correcting lines 199-205 an explicit task item.

7. **Task 5.2's "CI-equivalent glob invocation" is outcome-stated, not mechanism-constrained (standing lesson 3).** A hand-typed near-equivalent proves the glob the executor typed, not the glob that ships. Require: the command executed is the literal `run:` string extracted from the committed `ci.yml` e2e step, and the captured transcript must show (a) `e2e/zz-glob-proof.spec.ts` collected **by name**, and (b) the previously-wired specs also collected in the same run — so the proof simultaneously discharges task 3.3 rather than leaving it to inspection.
