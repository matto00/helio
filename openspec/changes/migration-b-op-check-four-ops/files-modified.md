## Root cause / debugging notes (systematic-debugging law)

Two test failures surfaced on first run of the new specs, both fixed with a probe-confirmed cause:

1. **`PipelineStepsOpCheckSeededRowsSpec`** — inserting `pipeline_steps` rows without a `root_id` failed `pipeline_steps_root_id_matches_parentless` (added by V98, requiring every parentless step to carry a non-null `root_id`). Root cause: the schema evolved since `V23__pipeline_steps.sql`'s original shape; a bare insert with only the V23-era columns is no longer legal on a fully-migrated table. Probe: the failing INSERT's own Postgres error message named the constraint. Fix: seed a `data_sources` + `pipeline_roots` row and set `root_id` on every inserted step.
2. **`PipelineStepsOpCheckOwnershipRequiredSpec`** — asserted `ex.getMessage should include("must be owner of relation")`; Postgres 14's actual message is `"must be owner of table pipeline_steps"`. Root cause: guessed wording instead of the real driver message. Probe: ran the spec and read the actual `PSQLException` message. Fix: asserted the real substring (SQLSTATE 42501 check was already correct and unaffected).
