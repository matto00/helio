## Decisions

**D1 - 6 e2e legs (owner ruling).** The owner answered HEL-1698's escalation `six-legs` on 2026-10-22
(`escalation.answered` in `.concertino/runs/HEL-1698/events.jsonl`), knowingly superseding the earlier ~8-leg
backend+e2e cap (`openspec/changes/archive/2026-10-05-halve-backend-ci-time/profile.md`; ci.yml "HEL-1288 (C8) at most
4 legs"): backend 4 + e2e 6 = 10 parallel jobs; a run goes from ~14 to ~16 jobs. Repo is public, so no minute charges.
`matrix.shard: [1..6]`, `max-parallel: 6`; the run step already passes `strategy.job-total`. Projection: test part
scales 4/6, slowest ~1.25x mean, +180 s overhead -> ~1030 s. 5 legs projected ~1200 s (no margin) - rejected.
Alternatives rejected: spec splits (no balance gain, D2), timeout raise (owner-only, does not meet the AC), API login
(changes what setup exercises).

**D2 - no spec splits.** `plan 6` gives 1382-1388 weighted s per leg; the largest file (717) fits one leg with room,
so LPT balance is already within 6 s. Splitting would be churn without measured gain.

**D3 - weights unchanged; regeneration made leg-count-aware.** Per-file weights are summed across all shard reports of
a run, so they do not depend on the leg count; `e2e/shard-weights.tsv` is not regenerated by this change. But
`weights` would refuse every future 6-leg run (`EXPECTED_SHARD_REPORTS = 4`). Change: default expected count = 6, with
`weights --legs <n> <runDir>...` for runs that predate the change (e.g. 4-leg runs); a run must hold exactly n clean
reports. `plan` with no count (today defaults to 4, `e2e-shard.mjs:288`) uses the same constant.
Add a selftest assertion that the default equals the `e2e` matrix length parsed from ci.yml (js-yaml, as
`check-ci-complete-needs.mjs` does), so the two cannot drift. Update the ci.yml comment "expects exactly the four shard
reports" and the e2e/README.md regeneration notes.

**D4 - composite action `.github/actions/e2e-setup/action.yml`.** Steps: setup-java 21 temurin, setup-sbt, sbt cache
restore (same key/paths), `scripts/e2e-backend.sh start`, setup-node 22 with npm cache, `npm ci`, `npm --prefix frontend
ci`, `npx playwright install --with-deps chromium`, `scripts/e2e-backend.sh wait`, and - behind input
`start-dev-frontend` (default `"true"`) - the Vite dev-server start loop. Composite `run` steps need `shell: bash`;
`working-directory` per step. Job-level `services`, `env`, `timeout-minutes`, checkout (must precede a local action),
test steps and uploads stay in each job (Actions does not allow services/env in a composite). `e2e-prod-build` uses it
with `start-dev-frontend: "false"` and keeps its build + `vite preview` steps. The HEL-1288 explanatory comments move
into action.yml. `e2e-slow.yml`'s `pull_request.paths` adds `.github/actions/e2e-setup/**` so this PR (and any future
edit to the action) proves the slow lane end to end. Step order and commands are byte-identical to today's.

**D4a - keep the pattern-kill guard's reach.** `scripts/check-ci-sbt-no-pattern-kill.mjs` `SCANNED` (lines 12-17)
lists `scripts/ci-sbt.sh`, `scripts/lib/ci-sbt-diag.sh`, `scripts/e2e-backend.sh` and `ci.yml`. Moving the e2e backend
setup into `.github/actions/e2e-setup/action.yml` would take it out of reach, so add that path (and
`.github/workflows/e2e-slow.yml`) to `SCANNED`. Its selftest asserts every `SCANNED` file is clean (selftest ~line 76).
Mutation evidence: add a pattern-kill line to action.yml IN A SCRATCH COPY OF THE TEXT passed to `checkText` (never
execute it), show it is reported naming the file, then show the real file passes.

**D5 - selftest `scripts/check-e2e-slow-results.selftest.mjs`** (a small local `test()` helper over
`node:assert/strict`, the same pattern as `e2e-shard.selftest.mjs`): RED cases
for skipped (names the test), zero ran, unexpected>0, missing stats, unreadable file (CLI exit 1), missing arg (exit 2);

## Risks / Trade-offs

- [Queueing against the account concurrent-job cap when several runs overlap] -> owner-accepted; the PR records each
  e2e leg's queue delay (`startedAt - run createdAt`) so a regression is visible.
- [Composite action changes step semantics] -> commands byte-identical; `shell: bash` explicitly; both e2e-slow (paths
  trigger) and e2e-prod-build run on this PR.
- [Projection is an estimate] -> the AC is judged only on real main runs; on a miss, report not met and revisit.
