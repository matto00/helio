### Non-blocking notes

- **Existing jest mocks will break, and the plan does not list them.** `MobilePanelStack.pullRefresh.test.tsx:28,39-53` mocks `usePanelData` with no `queueRefresh`. After D4 the registry calls `undefined` (TypeError), and its `refreshA/refreshB` call-count assertions (`:110-111`, `:187-188`, `:216`) target the wrong member. `MobilePanelStack.test.tsx:44-52,88,267` and `MobilePanelStack.provenance.test.tsx:28-38` build the same object literal and will fail typecheck once `queueRefresh` is a required member. When updating `pullRefresh.test.tsx`, separate the two mocks: the registry must call `queueRefresh`, and the per-panel `refresh` prop (`MobilePanelStack.tsx:111`) must not be called by a round. That gives a cheap unit-level kill for the "register `refresh` again" mutation, which D5 currently kills only in e2e.
- **StrictMode mounted-ref trap.** `main.tsx:113` wraps the app in `React.StrictMode`. The "mounted ref" in D2 must be set `true` in the effect body, not just initialised by `useRef(true)`. Otherwise the dev double-invoke cleanup leaves it false forever, drain never fires, and every queued round waits out the 15 s timeout. The e2e would catch this (step 4 sees 0 held on B), but the implementer should know why.
- **A stale `.finally` can drain while a newer dispatch is in flight.** If the fetch key changes mid-flight (an Output rebind), the effect dispatches anew (`:269`) and the old request's `.finally` (`:320`) then drains while the new request is still pending. That would put two concurrent requests on one panel, which the delta forbids. The underlying guard gap is pre-existing, and it is unreachable in the D5 fixture. A cheap fix is to drain at `.finally` only if this dispatch is still the latest (for example compare `keyAtDispatch` or `latestFetchRequestId`). Otherwise, list it under Risks.
- **The retry rule is under-specified on one point.** D2 says the drain "moves to" the CROSS_FILTER retry's settlement but does not say whether the outer `.finally` still clears `inFlightRef` (today it does, at `:320`). For the "never overlaps the retry" claim to hold against plain `refresh()` callers too, `inFlightRef` should stay true until the retry settles. Pin this down in the implementation.
