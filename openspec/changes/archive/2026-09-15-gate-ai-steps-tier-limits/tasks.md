- [C1] Probes key on the `ai-step` reason code, never on `autoRunnable` alone — another deny reason can make the flag false on its own.
- [C2] Every failure arm needs mutation evidence; a green assertion that cannot be made to fail proves nothing.
- [C3] Never commit with `-n`. Use timeout 600000 on every Bash call running commits, hooks, squash or tests.
- [C4] AI tests use a fake AiStepClient/transport with no network.
- [C5] No migration unless explicitly justified: V107 already admits all four ops and is the highest present; V108 only if truly needed.
- [C6] Do not absorb HEL-1109 (step-card UI) or HEL-1136 (op-menu) scope. Frontend changes only where the backend contract or a user-facing error forces them.
- [C7] spray-json drops None on the wire and sorts JsObject keys; Jackson readTree ignores trailing content. Normalize at the boundary and test with the field ABSENT.
- [C8] Reuse HEL-1100 D5 owner semantics (run AS the pipeline owner, never the triggering caller); do not invent new ownership semantics.
- [C9] Do not manufacture a change for AC1 if it is already satisfied on the base branch; report it as already satisfied instead.
- [C10] Preview-triggered AI model calls are authorized like submit (pipeline owner or editor grantee only); a viewer grantee previewing a closure containing an enabled AI step is denied with ZERO model calls.
- [C11] Every backend.execute call site must thread the pipeline owner. There are FIVE. Three are genuinely AI-reachable: step preview (:566), Output-backfill step/node arm (:710), and the real run (:945) — an unthreaded AI-reachable site is a SILENT fail-closed regression, not a compile error. Two run with Vector.empty steps so no AI step can evaluate: source-level preview (:494) and the Output-backfill source/root arm (:694); thread them for uniformity only and expect NO behavioural AI-client test there.
