## Context

See proposal.md (Why) and ticket.md (items 1-5 and run constraints). Current state on origin/main edd3a028f:

- The phone dashboard is `PanelList` -> `PanelGrid` -> `MobilePanelStack`. At viewport 768px and below `PanelList` renders, above the grid, `DashboardRefreshLine` (the "refreshed 9h ago" caption, `frontend/src/app/dashboardMeta/`, a fixed-height `calc(var(--text-xs) * 1.6)` slot so it never shifts the cards; reserved and `aria-hidden` while the fact is unknown on a pipeline-fed dashboard; absent on a dashboard with no pipeline-fed panels) and `DashboardChipRow`.
- `MobilePanelStack` owns a `PullRefreshRegistry` (`pullRefreshRegistry.ts`) in `useState`, provides it via `PullRefreshContext`, subscribes to its busy changes (announcing "Refreshing"/"Refreshed" in an always-mounted `role=status` region), and drives `usePullToRefresh`. Output-bound panels register via `usePullRefreshRegistration`. `registry.start()` returns false when busy or with no entries.
- The indicator renders while `pull.active || busy`; `pull.follows` is true only while a Full-motion pull is engaged/held. After busy turns false, `usePullToRefresh` settles the held stack from `PULL_HOLD_PX` to 0 over `--motion-duration-move`, with phase `idle`, so `PullRefreshIndicator` maps it to the `pulling` label "Pull to refresh" (item 4).
- `--pull-indicator-height: 48px` (MobilePanelStack.css) vs `PULL_HOLD_PX = 48` (usePullToRefresh.ts) (item 3).

## Decisions

**D1. One registry, owned by a DOM-less provider mounted unconditionally in `PanelList` (skeptic-design-1 CR1).** The refresh button lives on the refreshed line, a sibling of the grid, so the registry must be shared above both. Add `PhoneDashboardRefreshProvider` (in `features/panels/ui/grid/`): a pure context provider that renders NO DOM element of its own. It wraps `PanelList`'s ENTIRE returned `<section>` subtree, at every width, as the same element for `PanelList`'s whole lifetime (never inside the `isPhoneShell` branch, never conditionally), so `.panel-list__zoom-container` (HEL-528's single always-mounted element, `PanelList.tsx:405-432`) is never remounted by crossing 768px. Ownership:
- **Registry instance:** created once in the provider (`useState(() => new PullRefreshRegistry())`); the provider, and only the provider, calls `registry.dispose()` on its own unmount. `MobilePanelStack` uses the context registry when present and MUST NOT dispose it (today's stack cleanup calls `registry.dispose()`, which clears every listener — that call moves to the fallback path only). With no provider (unit tests, any other mount) the stack creates and disposes its own fallback instance exactly as today.
- **Status region (`role=status`, "Refreshing"/"Refreshed"):** stays owned by `MobilePanelStack`, unchanged. The stack subscribes to the (shared) registry's busy changes, so a button-started round is announced by the same region. This is sound because the button renders only while an output-bound panel is registered, and every registered panel lives inside the mounted stack.
- **Regression check:** a test (jest or e2e) asserts that crossing 768px in both directions keeps the same `.panel-list__zoom-container` DOM node and a non-zero grid container width.
Alternatives rejected: a phone-only wrapper (remounts the zoom container — the HEL-528 width-0 bug); a second registry/button inside the stack (a new row shifts the cards, HEL-1646); a Redux-level dashboard refresh (there is none; the registry is the one fan-out).

**D2. Registry extensions.** Add an observable count of registered entries (`subscribeEntries`/`hasEntries`, notifying only when the count crosses 0 <-> >0 or changes, never per render) so the button renders iff at least one output-bound panel is mounted, and record whether the current round was started by a pull or the button (`start(source)`), exposed to the stack so the pull indicator renders for pull-started rounds only (D4). `start()` keeps its current contract (false when busy or empty).

**D3. The button (reversible UI decision, listed in the PR; skeptic-design-1 CR2/CR3).** An icon-only `<button type="button" aria-label="Refresh dashboard" title="Refresh dashboard">` with lucide `RotateCw` at `ICON_SIZE.sm` (14px), at the trailing (inline-end) edge of the refreshed line.
- **Hand-rolled under DESIGN.md §5's documented sub-24px exception.** `IconButton`'s smallest size (`xs`, 24px) is taller than the line's fixed `calc(var(--text-xs) * 1.6)` (19.2px) slot, so using it would push the cards down (HEL-1646 layout-stability rule). The painted box is exactly the line's height (19.2px square, glyph 14px centred), Ghost recipe colours (`--app-text-muted`, hover `--app-surface-soft`), `--app-radius-sm`, §8 focus ring. It carries both `aria-label` and `title`; the exception is cited in a code comment.
- **Escaping the clip.** Today `.dashboard-refresh-line` has `overflow: hidden`, which would clip a `::after` expander to 19.2px. The line element drops `overflow: hidden` (height stays fixed); the fact text moves into an inner span that carries `overflow: hidden; text-overflow: ellipsis; white-space: nowrap; min-width: 0; flex: 1`, so long copy still cannot grow the line. The button is a flex sibling of that span, never inside an `aria-hidden` subtree; the reserved state keeps an `aria-hidden` empty span (not the whole line) so the button stays exposed.
- **44px hard floor, anchored to the panel list's padding box (skeptic-design-2 CR2).** `.panel-list` itself has `overflow: hidden` (`PanelList.css:8`), with (on the phone) 20px top and 12px side padding, so the tap area must stay inside `.panel-list`'s padding box. The tap area is a `::after` hit expander of exactly 44x44px with: its TOP anchored to the top of the panel list's padding (`top: calc(-1 * var(--space-5))` relative to the line, i.e. y = 0 of `.panel-list`), so it spans y = 0..44 against the chip row starting at about y = 47.2 (3.2px spare; a CSS comment records that this assumes the root font size keeps `--text-xs * 1.6` + the 8px gap at or above that, about a 14.9px root); and its INLINE-END edge anchored to the button's inline-end edge (`right: 0`), extending 44px toward the start, so nothing crosses `.panel-list`'s right edge. No "shrink the expander" fallback: if 44x44 cannot fit inside `.panel-list`'s box without overlapping the chip row's tap area at 375 or 430, the executor stops and escalates (non-reversible layout call).
- **Measured, not CSS-text-checked (C1).** `expectTapExpander()` only reads CSS text; task 2.4 measures the real tap area with `document.elementFromPoint` at 375 and 430, with sample points derived from the expander's actual box (read via `getBoundingClientRect` of the button plus the computed `::after` offsets): points 1px inside each of the box's four corners and its centre hit the button; a point 1px below the box's bottom edge does not hit the button; the centre of the first chip in the chip row and a point 1px inside its own tap area's top edge still hit the chip (the chip row keeps its own taps); the box lies fully inside `.panel-list`'s bounding rect.
- **Visibility.** Rendered iff the registry has at least one entry (D2), on the phone shell only. When output-bound panels exist the line is already reserved from first paint (output-bound panels are pipeline-fed; `DashboardRefreshLine` reserves the slot for pipeline-fed dashboards, HEL-1646) — verify; if any case renders the line late, keep the button out of that case rather than introduce a shift, and record it.
- **Initial busy state.** Because the registry now outlives the stack, `MobilePanelStack` initialises its `busy` state from `registry.busy`, not `false` (skeptic-design-2 note).
- **Busy.** The glyph is replaced by the shared `Spinner` at the same painted size, the button gets `aria-disabled="true"` (not `disabled`, so focus is kept), and activation is a no-op (`registry.start()` already returns false while busy).
- `DashboardRefreshLine.test.tsx`'s reserved-slot assertions are updated for the moved `aria-hidden`, keeping their intent (no placeholder text exposed, same fixed height).

**D4. Indicator during a button round.** The pull indicator renders only while a pull is engaged/held or for a pull-started busy round. A button-started round shows its busy cue on the button only (no snap pill straddling the first card, no double spinner), and the stack does not translate. A pull while a button round runs is ignored (existing `busyRef` guard). Reversible UI decision, listed in the PR.

**D5. Item 4 — settle label.** Add a completed indicator state: `usePullToRefresh` exposes that it is settling after a refresh round (e.g. phase `done` or a `settlingAfterRefresh` flag set when the busy-false effect starts the settle and cleared in its `clear`), and `PullRefreshIndicator` maps it to the label "Refreshed" with a static check glyph (lucide `Check`, reversible UI decision) instead of the arrow. Under Subtle/Off nothing settles (the content never translated), so the indicator unmounts immediately as today. Measure the settle window before/after under Full motion with an e2e/page probe sampling the label each frame, and record the numbers in the PR.

**D6. Item 3 — one source of truth.** `PULL_HOLD_PX` in `usePullToRefresh.ts` stays the source of truth. Add a jest guard (e.g. alongside `motionPrimitiveLiterals.test.ts` or in `MobilePanelStack.pullRefresh.test.tsx`) that reads `MobilePanelStack.css`, extracts the `--pull-indicator-height` declaration, and asserts it equals `${PULL_HOLD_PX}px`; record a mutation (change either value) that turns it red. The CSS comment is updated to name the guard. Alternative rejected: setting the property inline from JS — the stylesheet still needs a declared default for the custom-property guard, which reintroduces the duplicate literal.

**D7. Item 2 — collapsed chart card.** Investigation under the systematic-debugging law: reproduce on base under Full motion at 375 (repeat runs; record the hit rate), capture the chart's DOM/size at first paint and after settle, and confirm a root cause with a probe before any fix (likely candidates to test, not assume: the entrance animation's transform/scale or `contain`/size at the moment the chart library measures its container, or the chart's own enter animation being interrupted by a re-render). Fix at the root cause, with a regression check (jest where the mechanism is unit-observable, otherwise an e2e repeat run with recorded before/after hit rates). If not reproducible within the `DEBUG_ATTEMPTS` budget, the AC's "measured" applies: record the attempts, the rates and the evidence in the PR and list it as a follow-up candidate — no speculative fix.

**D8. Item 5 — triage only.** Read `hel1575-dashboard-tabs.spec.ts:593` and run it under load (`--repeat-each`, 2 workers, alongside the full suite where feasible) to classify the cause (test-side timing vs app defect). If the fix is a small, test-only change with a probe-confirmed cause, include it; otherwise record the triage (evidence, hypothesis, suggested owner) in the PR and hand-back as a follow-up candidate. It must not grow this ticket.

## Risks / Trade-offs

- [The 44px tap area cannot fit] -> D3 hard floor; escalate rather than shrink.
- [Lifting the registry remounts the zoom container] -> D1 DOM-less provider mounted unconditionally, plus the 768px-crossing regression check.
- [Lifting the registry changes the stack's mount ownership] -> fallback instance keeps the stack self-sufficient; existing `MobilePanelStack.pullRefresh.test.tsx` must stay green unchanged in intent.
- [Item 2 is not reproducible headless] -> D7's "measured" path; no speculative fix.
- [Placement is a product call the owner may revisit] -> reversible, listed under "UI decisions taken overnight" with screenshots.
