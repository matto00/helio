## Decisions

1. **echarts via a MODIFIED delta, plus a direct retitle of four scenario titles.** openspec 1.10.0 cannot retitle a scenario through a MODIFIED delta (`validate` rejects "omits scenario(s)"; precedent `archive/2026-10-10-split-pipeline-detail-remainder`). The delta therefore keeps the original titles with corrected bodies; the executor retitles, in lockstep in BOTH the canonical spec and the delta, the four titles that would otherwise stay false or overbroad: "Unbound chart panel shows an empty default chart" -> "A chart Output with no rows shows a no-data state"; "Bound chart panel with no field mapping shows empty state message" -> "A chart Output with no yAxis mapping auto-detects numeric series"; "A legacy stored scatter+aggregation combination still ignores the spec" -> "A non-aggregating chart type ignores an aggregation spec"; "Chart panel with unknown chartType falls back to line" -> "An unrecognised Output chart type falls back to line". Then `validate --strict` and a simulated archive on a scratch copy must pass. The new requirement text never names `typeId`, so `grep typeId` is empty on the delta and Purpose line immediately, and on the archived echarts spec in the simulated archive (the canonical requirement body only changes at archive). The Purpose line is a direct edit (Purpose is not delta-able).
2. **write-path-audit:** the requirement scenario via the delta (batched model). The `## Write Path Reference` tables are not requirements, so direct edits: rows 7 and 8 become one `POST /api/panels/updateBatch` row for staged title/appearance edits (payload shape read from `panelPayloads.ts`/`buildBatchRequest`, at most one call per flush); payload details 7/8 restated likewise (no `chart` field claim); row 9 trigger stays the Output swap but cites `OutputPicker.tsx`; call-volume rows/totals recomputed (title/appearance edits fold into flushes; "data binding saves" becomes Output swaps); Source Locations: `PanelDetailModal.tsx` role = staged appearance edits, add `OutputPicker.tsx` (Output swap) and `usePanelTitleEditing.ts` (staged title edits) if missing; Key observation L176-180 aligned with the no-debounce row 1. The simulated archive must show the reference section survives intact.
3. **usePanelPolling rename `typeId` -> `outputId`** (matches the caller's argument); doc comment reworded; dependency array updated. `usePanelPolling.test.ts`'s `typeId` variable and test titles are renamed too (assertions unchanged). Identical behaviour, proven by those tests passing.
4. **CLAUDE.md:** decided by evidence, not by reading alone. Probe on this worktree's backend (port 9953): signed-in GET on an owned, non-public dashboard -> expect 200 with items; unauthenticated GET on the same id -> expect 404/403; plus a grep showing no same-path route under `authenticate`.
