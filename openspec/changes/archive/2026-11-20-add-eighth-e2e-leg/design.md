## Goals / Non-Goals

**Goals:**
- 8 e2e legs, with every artifact keyed to the leg count agreeing (matrix, `max-parallel`, `DEFAULT_E2E_LEGS`, docs).
- Weight table regenerated from CI evidence that includes the two unweighted specs.

**Non-Goals:**
- Raising `timeout-minutes` (owner ruling); a larger, paid or pinned runner class (owner ruling).
- Splitting the popover specs or any other spec; changing Playwright `workers`; any app code or migration.
- Changing the backend job's 4 legs.

## Risks / Trade-offs

- [8 legs may still exceed 1200 s on a 1.4x host, since setup does not shrink and the suite grew] → Measure and state
  the gap with its cause (AC allows it); do not raise the timeout. A further remedy is a new owner decision, filed as a
  follow-up, not decided here.
- [Account-wide concurrent-job pool: 12 parallel jobs per run, more queueing when lanes overlap] → Owner accepted one
  more runner per run; leg wall is measured from job start, so queueing does not inflate it.
- [Weights taken from 7-leg runs] → Weights are per-file sums across all reports, independent of leg count (stated in
  e2e-shard.mjs); `--legs 7` only sets the expected report count.
- [Measurement runs cost CI] → Capped at AC (5) + 1.
