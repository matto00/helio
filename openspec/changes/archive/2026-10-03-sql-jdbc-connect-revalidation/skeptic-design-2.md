### Non-blocking notes (for the executor)
- mysql wraps non-SQL exceptions: `ConnectionImpl.connectOneTryOnly`/constructor convert any thrown Exception (incl. a RuntimeException refusal) into a `SQLException` (cause chain preserved). So `SqlConnectorDriver.connect`/`execute`'s `case SqlEgressRefusedException(msg)` will NOT match a factory refusal; it will surface as the generic "SQL execution failed" unless connect() unwraps the cause chain (or the test asserts via the cause). Pick a recorded approach (walk causes in connect and rethrow the typed refusal) so tests asserting "egress refusal" are not vacuous. pgjdbc likewise wraps in PSQLException.
- pgjdbc loginTimeout thread hop (above): consider explicitly adding `loginTimeout=0`/asserting it, or record that the production default fail-closed fallback applies; positive-path tests with `connectIsBlocked = _ => false` would silently use the production predicate if a hop occurred.
- Database whitelist `^[A-Za-z0-9_.$-]+$`: Java `$` also matches before a trailing line terminator, so "db\n" passes; use `matches`/`\z`. Same quirk in the existing host charset (backstopped by the URI round-trip). Add a trailing-newline case to the test.
- mysql leaves `rawSocket` set to the unconnected validating socket when a non-SocketException aborts the loop; close it in the refusal path.
- TLS proof against embedded Postgres may need cert plumbing; keep the "state exactly what changes" fallback.
