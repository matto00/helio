## Skeptic Report — design gate (round 1, skeptic-design-1.md)

### What I verified (with evidence)
- Read ticket.md (owner ruling), proposal, design, tasks, spec delta.
- Extracted pgjdbc 42.7.13-sources.jar and mysql-connector-j 8.3.0-sources.jar from the coursier cache and read them.
- pgjdbc: `SocketFactoryFactory.getSocketFactory` -> `ObjectFactory.instantiate(..., tryString=true, socketFactoryArg)`. Constructor order is `(Properties)` FIRST, then `(String)` if arg non-null, then no-arg. `PGStream.createSocket` calls `socketFactory.createSocket()` (NO-ARG), then `socket.connect(new InetSocketAddress(host, port), timeout)` (host resolved by the JDK there). So the hook is a SocketFactory whose `createSocket()` returns a Socket subclass overriding `connect(SocketAddress,int)`; the factory never sees an address itself. Design D1/D2 do not say this.
- mysql-connector-j 8.3.0: `com.mysql.cj.protocol.SocketFactory.connect(String host, int port, PropertySet, int loginTimeout)` receives a HOSTNAME STRING, not a resolved InetSocketAddress. `StandardSocketFactory.connect` does `InetAddress.getAllByName(host)` itself and `rawSocket.connect(new InetSocketAddress(addr, port))` per address, via protected `createSocket(PropertySet)`. Design D1 ("the driver asks the factory to connect to an already-resolved InetSocketAddress") is FALSE for MySQL. A factory implementing connect(String,...) and validating needs either its own resolve (the TOCTOU again) or, correctly, subclassing StandardSocketFactory and overriding `createSocket` to return a validating Socket subclass. Also the loop only swallows `SocketException`; the refusal exception type matters (a non-SocketException aborts, a SocketException makes the driver try the next record).
- pgjdbc `Driver.parseURL`: URL query values are priority 1, above the Properties passed to `getConnection`. mysql URL params behave likewise.
- `SqlSourceConfig.database` (DataSourceProtocol.scala:152/489) is interpolated unvalidated into the URL by `buildJdbcUrl`; grep found no validation of database/dialect anywhere in src/main. So a source with `database = "x?socketFactory=javax.net.DefaultSocketFactory"` (pg) or `x?socketFactory=com.mysql.cj.protocol.StandardSocketFactory` (mysql) overrides the guard's factory and fully bypasses it. This is a bypass of the very control this ticket adds; the design never mentions it.
- JDBC open sites: only `SqlConnectorDriver.connect` (via execute/testConnection/inferSchema/fetch) and `PipelineRunNotifyBus.scala:186` (app DB) use DriverManager in src/main. Claim of single chokepoint holds. Callers also exist in PipelineService:1633, InProcessPipelineEngine:667, SourceService, AssistantToolExecutor/PipelineProposalService (create/validate paths) - the dialect refusal must cover create paths beyond SourceService.createSql (pipeline create with inline SQL source, assistant proposal apply), which tasks.md does not list.
- App pool untouched: sound; the factory is attached only in `connect`. Cloud SQL `postgres-socket-factory` is also on the classpath, unaffected.
- Rebinding test strategy: realistic. Java 21; use host `localhost` (injected guard resolver says public; the driver's own resolution lands on loopback), embedded-postgres (zonky 2.0.7, Test dep) for pg, counting ServerSocket for mysql. Mutation-failable in principle. The injected `isBlocked` must NOT block loopback for the guard lookup while the factory must still block it, so the registry-keyed override has to be designed so the test's guard-permissive predicate does not also reach the factory (otherwise the test can't tell the factory from the guard). Design gives no concrete mechanism for this.
- TLS claim: structurally right for pg (factory yields plain Socket, pgjdbc wraps it); for mysql StandardSocketFactory.performTlsHandshake wraps rawSocket (subclass keeps this). Needing a TLS-enabled embedded Postgres is unverified feasibility; design does allow "state the exact change", acceptable.

### Verdict: REFUTE

### Change Requests
1. Fix D1 for MySQL: state that `connect` receives a hostname, not an InetSocketAddress. Specify the mechanism (subclass `StandardSocketFactory`, override `createSocket(PropertySet)` returning a Socket whose `connect(SocketAddress,int)` validates the `InetSocketAddress`'s InetAddress, throwing before connecting) and the exception type's effect on the per-address retry loop. Likewise state the pgjdbc mechanism (createSocket() no-arg returning a validating Socket subclass; connect target is already resolved).
2. Close the URL-parameter-injection bypass: `database` (and any other field interpolated into the URL) is unvalidated, URL params outrank Properties, so a user can override `socketFactory`/`socketFactoryArg`. Add a requirement and task: reject (400 at create, typed refusal at connect) or strictly encode `database` containing `?`, `&`, `;`, `/`, `#`, `%`, whitespace, etc.; assert the final URL has no user-controlled query component; add a test that `database="x?socketFactory=..."` cannot disable the guard (mutation-failable). Add a spec scenario.
3. D2: correct the pgjdbc contract (Properties ctor is tried first, then String, then no-arg) and pick one concrete key-carrying mechanism per driver (mysql: name the exact PropertyKey, e.g. `connectionAttributes`, or use a thread-local scoped to the synchronous `DriverManager.getConnection` call). Explain how the test's permissive guard predicate is kept separate from the factory's predicate so the rebinding test is meaningful.
4. Extend D3/tasks to every create/validate path that accepts a SQL config (PipelineService ~1621, PipelineProposalService ~214, AssistantToolExecutor, DataSourceConfigCodec), not only `SourceService.createSql`; make the unknown-dialect refusal live in one shared place and add tests for each path.

### Non-blocking notes
- Consider re-checking `isBlockedAddress` handles IPv4-mapped IPv6 and that the factory also rejects unresolved addresses (already planned).
- TLS proof against embedded Postgres may need cert plumbing; plan the fallback wording now.
