### Verdict: REFUTE

### Change Requests

1. **design.md D2 / D1: resolve bar thickness at design time, not as a task-1.1 STOP.** Measured: 29px bars with a 1px gap at 24px (same at the 20px phone size, both faces). Revise D1/D2 to a mechanism that leaves a visible gap between line bars and a bar thickness comparable to today's ~20px (`--text-xl`), without changing line-height or font-size (layout). The vertical `mask-image` on the clone span shown above works (20px bars, ~10px gap, height unchanged) but clips the corner rounding — specify how ends stay rounded or justify the result. State the target thickness/gap numerically (e.g. bar ≈ `--text-xl`, gap >= `--space-2`) so "matches the existing skeleton look" has an acceptance signal. If you conclude no layout-neutral mechanism can give a gap, that is when to ESCALATE — with these measurements attached.
2. **design.md D4 / tasks.md 2.1: add an assertion that catches merged bars.** For consecutive fragments, assert the vertical gap (`rects[i+1].top - rects[i].bottom`) is >= the chosen minimum and each bar's painted height is within the chosen range, at 431/480/604 and the 320-430 band (20px font), light and dark. Add a mutation that removes the thickness/gap mechanism and must turn the spec red. Also correct D1's description of what `clone` does (per-fragment rounded ends/gradient; per-line painting comes from `display: inline`) and say which assertion catches each mutation.
3. **tasks.md 3.1: keep an explicit dependency on Skeleton.css.** If `HomeOpeningLine.tsx` no longer renders `<Skeleton>`, it must still import the stylesheet that defines `ui-skeleton` (e.g. a side-effect `import "../../../shared/ui/Skeleton.css"`), not rely on sibling components; add a unit assertion or comment explaining the dependency.
4. **tasks.md 1.1: name the browser.** The MCP browser here is Chrome 156; the guard runs in Playwright 1.55's bundled Chromium (and the helio1678-ci/dv images). Task 1.1 must record the exact Chromium build the e2e uses and re-measure thickness/gap there and with fonts blocked (DejaVu fallback face, which has different overrides: 106.82%+28.2% at 91.42% size-adjust).
