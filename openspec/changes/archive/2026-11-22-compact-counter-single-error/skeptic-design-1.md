### Non-blocking notes

- Task 1.1, second test: to observe "the alert is emptied at the second step's start", the second submit must be held pending, for example with a deferred promise, before you assert empty, then rejected. Otherwise the empty state is never observable. The implementer should do it that way rather than asserting only the final state.
- D3 (a hint stays visible while the alert shows the error) is a small visual change from today's "error replaces hint". It is harmless, but if the e2e or screenshots use a counter with `helpText`, check that the hint and the alert read cleanly together in both themes. Otherwise mention it in the PR body alongside the in-flight empty-description trade-off.
- A test may need to scope "exactly once in the panel" to the panel container rather than `document`, to exclude the toast provider's region if it is rendered in the jest harness. State the scope in the test.
