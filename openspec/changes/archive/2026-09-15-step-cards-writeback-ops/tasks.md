## Standing Constraints

- [C1] Every status-code claim in a spec, design or report must cite the `ServiceError` the code actually returns (a config rejection is 422 `UnprocessableEntity`; only an unknown step type is 400) — never an assumed 400.
- [C2] A guard test must be proven failable in the direction of its STATED PURPOSE by mutating its source of truth, not by mutating a hardcoded twin of the value under test.
- [C3] A task may be marked `[x]` ONLY when the verification it mandates actually exists AND discriminates the defect it targets. If a mandated verification is wrong, infeasible or narrower than written, narrow the task text or leave it unchecked — never mark it done.
