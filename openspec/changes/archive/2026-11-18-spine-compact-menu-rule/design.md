## Context

See proposal.md (Why). Current state on main 361c22f22, `frontend/src/features/pipelines/ui/spine/PipelineSpine.css`:

- `.spine-card__menu` (Source and Output cards) has no opacity rule: always visible, always operable.
- `.spine-row__menu` is `opacity: 0`, revealed by `.spine-row:hover`, `.spine-row:focus-within` and `.spine-row--selected` (all widths). It stays IN FLOW, so an unselected row reserves its width while hidden.
- `@container spine-column (max-width: 226px)` (HEL-1608 compact block) turns `.spine-row__select` into a 4-column grid (`auto minmax(0,1fr) auto auto`, `column-gap: var(--space-2)`): number spanning both lines; title on line 1 spanning columns 2–4; summary / markers / count on line 2. The menu is taken out of flow (`position: absolute; right: 0`, centred), `pointer-events: none`, and the selected row's permanent reveal is cancelled (`opacity: 0`) — so the selected row's ⋮ is hover/focus-only in compact mode.
- `.spine-row__markers:empty { display: none }` exists only inside the compact block; the grid still keeps the markers track, so an empty slot costs one 8px column gap (item 2). Outside compact the empty markers span is a flex item of the select (`gap: var(--space-3)`), costing a 12px gap.
- `frontend/src/features/pipelines/ui/pipelineHoverGating.css.test.ts` (HEL-1668) allowlists the whole compact block as ONE unit (`ancestor: COMPACT_CONTAINER, selector: "*"`) and the regular `.spine-row:hover .spine-row__menu` reveal. Any new `:hover` selector outside those units must be inside `@media (hover: hover)`.
- Narrowest desktop spine: track 180px, `.spine-body__spine` padding `--space-4` each side → 148px content box. A lane is indented by `--space-5`. The trigger is `--control-sm` (24px fine pointer, 28px coarse with a 44px expander).

## Goals / Non-Goals

**Goals:** one ⋮ rule (item 1), no empty-marker gap (item 2), a spec that proves compaction (item 3), a recorded decision on 1100px truncation (item 4), corrected spec wording (item 5).

**Non-Goals:**
- No change to the compaction threshold (226px content box) or to the spine track formula.
- No change to the shared popover / `usePortalPopover` / panelFit code (concurrent HEL-1762) or the open-dialog registry (HEL-1736). `ActionsMenu` is used as is.
- No step-label renaming, no new tooltip on the title (the row's `title` is the HEL-985 node path; shadowing it is out of scope).
- Phone rows (`spine-row--phone`) are untouched.

## Decisions

### D1. The ⋮ rule: a standalone item's ⋮ is always visible; unselected step rows reveal on hover/focus

Rule, at every desktop width: **Source cards, Output cards and the selected step row always show their ⋮; an unselected step row shows it on hover or keyboard focus.** Compact mode stops being an exception and returns to the same rule as the regular spine.

Why this and not the alternatives:
- *All three hover/focus-only* (make cards match compact rows) is rejected: a card's surface is itself a button (`.spine-card__open` opens the source/Output), so on touch there is no hover to reveal its ⋮ — the first tap activates the card. Its actions (Edit source, Output actions) would become unreachable by touch except via keyboard. DESIGN.md §5 (HEL-1675) treats a hover reveal as a named exception, not a default; widening it to cards contradicts that.
- *All three always visible including every unselected row* is rejected: at the 148px content box an always-visible in-flow ⋮ on every row costs 24–28px per row and pushes depth-1 lane titles toward/below the ~60px readability floor (100 − 24 − 20 ≈ 56px), and it makes the quiet spine (DESIGN.md §0 "quiet controls", HEL-1579 D5) noisy.
- *Chosen rule* keeps every ⋮ reachable on touch with no hover: tapping an unselected row selects it (that is the row's primary action), and the selected row's ⋮ is then permanently visible and operable. Keyboard: an unselected row's trigger stays in the tab order (opacity-hidden, never `display/visibility`), and `:focus-within` reveals it. Cards are unchanged.
- **A hidden trigger never takes a press; the press selects the row (skeptic design-1 CR2, design-2 CR1).** On main the regular (non-compact) hidden trigger is `opacity: 0` but still hit-testable, so on a no-hover touch device above 768px a tap on an unselected row's right end opens that row's menu instead of selecting it, which breaks the touch path this rule depends on. Making the hidden menu `pointer-events: none` alone is NOT enough: in regular mode the menu is an in-flow flex sibling AFTER the `flex: 1` select, so its box is outside the select's and a press there would fall through to the `.spine-row` div, which has no click handler (a dead zone; design-2 reproduced this). Option taken (a variant the round-2 report did not list, chosen over its (a)/(b)/(c)): **the select's hit box extends under the menu's slot.** On desktop rows that render a menu, the select gets a negative right margin equal to the menu slot's width and an equal extra right padding, so its CONTENT box (and therefore the title, summary and count layout and the title width) is unchanged to the pixel, while its BORDER box now runs to the row's right edge underneath the menu. The menu is stacked above the select (`position: relative; z-index` on the menu slot). While hidden, the menu is `pointer-events: none`, so a press at its position lands on the select button and selects the row; once enabled for pointer input (the restore set in the next bullet: selected row, focus inside the menu itself, or row hover under `@media (hover: hover)`) it is `pointer-events: auto` and on top, so its trigger takes the press. Revealed for OPACITY (row hover, row focus-within, selected) and enabled for POINTER input are deliberately two different state sets. Why not the others: (a) overlaying the regular-mode menu would let a hover-revealed ⋮ cover the row count at every desktop width, including 1280px, a visible change to HEL-1579's one-line row the ticket did not ask for; (b) a click handler on the row div adds a non-focusable interactive element (jsx-a11y `no-static-element-interactions`) duplicating the select button's action; (c) accepting a dead zone contradicts this decision's own touch premise. A11y: no change to roles, names or tab order (the select is still one button; the menu trigger is still a separate button in the tab order; `pointer-events` does not affect keyboard focus, and `:focus-within` still reveals and enables it). The select's hover tone now spans under the hidden menu slot, so the hovered row reads as one surface to the row's right edge; the selected row's accent wash is on the row and is unchanged. Hover-gating: see the guard-impact statement in the next bullet (one new hover selector, gated inside `@media (hover: hover)`, written as its own rule; the existing allowlisted opacity reveal rule is unchanged). The extension's width is the menu slot's own width token (the trigger is `--control-sm`; the executor reads its computed width under fine and coarse pointers rather than assuming 24px), applied only to desktop rows that actually render a menu (phone rows render none; `:has(> .spine-row__menu)` or a TSX modifier class, executor's choice). Compact mode needs no hit-box extension (its menu is already absolute over a full-width select), but its `pointer-events` restore set DOES change, to the same set as the regular rules (next bullet).
- **Which states re-enable the hidden ⋮ (skeptic design-3 CR1).** A state that the press itself creates must never re-enable the trigger before the click is targeted: on touch, Chromium applies sticky `:hover` and the select's focus (`.spine-row:focus-within`) during the tap and re-hit-tests the release, so a restore keyed to either sends the click to the trigger (menu opens) or to the row div (dead zone); design-3 reproduced both. So `pointer-events: auto` on `.spine-row__menu` is restored ONLY by: `.spine-row--selected .spine-row__menu` (selected row); `.spine-row__menu:focus-within` (keyboard focus inside the menu itself, i.e. the trigger); and `.spine-row:hover .spine-row__menu` written INSIDE `@media (hover: hover)`. This applies in both the regular rules and the compact block (the compact block on main restores on ungated row `:hover`/`:focus-within`, the same defect). The OPACITY reveal may stay on the row's `:hover`/`:focus-within` (the existing allowlisted mixed rule, unchanged), so a keyboard user still sees the ⋮ when the row's select is focused. Hover-gating guard impact: one NEW hover selector, inside `@media (hover: hover)` (permitted, not an allowlist entry), in each of the regular rules and the compact block; the ungated `pointer-events` restore that the compact block has today is removed; the allowlist itself is unchanged except that the compact unit no longer contains an ungated `pointer-events` hover restore. Keyboard (design-3 CR1(d)): with the select focused the ⋮ is visible but not pointer-operable until hovered or the row is selected; this is acceptable because the keyboard path to the ⋮ is Tab onto the trigger itself (which matches `.spine-row__menu:focus-within` and enables it), and a pointer user who reaches it hovers it (fine pointer) or selects the row first (touch). Contract scope: the "press selects the row" guarantee is for NO-HOVER input (touch). With a hovering pointer the ⋮ is visible at press time and opening it is the intended hover reveal. Residual risk: a touch laptop whose primary pointer is fine matches `(hover: hover)`, so a touch tap there can still restore `pointer-events` via sticky hover and open the menu; Playwright's touch emulation cannot reproduce that device class, so this is recorded, not claimed covered.

### D2. Where the compact selected row's ⋮ goes: the end of the summary line

In compact mode the selected row's ⋮ cannot simply return to flow beside the select: it would take its 24–28px out of the TITLE line too (≈76px top-level, ≈56px for a depth-1 lane row at 148px content — under the floor). Line 2 (summary · markers · count) is where HEL-1608 already decided width is shed first ("the count keeps its full width and the summary ellipsizes first"). So:

- On a compact *selected* row, the select's grid gains a trailing track of the trigger's width on line 2 (the title still spans the full width of line 1 — it never loses width to the ⋮).
- The ⋮ (still the sibling `.spine-row__menu` element; no markup nesting inside the button) is positioned over that trailing cell: right edge at the row's right edge, vertically aligned to line 2. It is `opacity: 1; pointer-events: auto` with no hover dependency, and has a transparent background (the trailing cell under it is empty, so it needs no opaque backing; this also means its box cannot paint over the title's descenders if it rises into line 1).
- The summary ellipsizes earlier; the count keeps its full width; neither is covered by the trigger. The trigger's box may extend a few px above line 2 into line 1's leading at the far right; this is acceptable only if the title's visible text is not covered there (verified with `elementFromPoint` sampling of the title's visible box, including its bottom band, at both the 24px fine-pointer and 28px coarse-pointer trigger sizes, D5). If measurement shows the trigger's GLYPH covering the title, the executor raises the trigger's vertical position to fully within line 2's band by aligning it to the row's bottom padding instead, and records the measurement; neither variant changes the rule.
- The executor MAY add a modifier class or data attribute to the row (e.g. for `:has()`-free selection) in `SpineStepRow.tsx` if CSS alone cannot express it; no change to the accessible name, roles or menu items.
- Unselected compact rows keep HEL-1608's overlay reveal (absolute at the row's right end, solid tone backing, `pointer-events: none` until enabled by the D1 restore set: selected, focus inside the menu itself, or row hover under `@media (hover: hover)`; its opacity reveal stays on row hover/focus-within). All of this stays inside the compact `@container` block so the hover-gating guard's one-unit allowlist still covers it; any hover rule outside that block is written inside `@media (hover: hover)`.

### D3. Empty markers take no space, at every desktop width (items 2 and 4)

- Compact: when the markers slot is empty, the grid drops its markers track (the count moves to the track after the summary), so the summary–count gap is exactly one `column-gap`. Implementation choice is the executor's (`:has(.spine-row__markers:empty)` re-templating, or a row modifier set from the TSX when there are no markers); the spec scenario is the contract.
- Regular (non-compact): an empty markers slot leaves the flow on DESKTOP rows only — scoped as `.spine-row:not(.spine-row--phone) .spine-row__markers:empty { display: none }` (skeptic design-1 CR3), so phone rows, which render the same span, are untouched as the Non-Goal says — reclaiming the 12px flex gap for the title. Markers appearing/disappearing already reflow the title by the marker's own width, so this adds no new kind of movement.

### D4. Item 4 decision: the 1100px truncation is accepted after D3

At 1100px the spine is above the compaction threshold by design (HEL-1608's tuned trade-off). With D3 the title gains the 12px the empty markers slot was wasting. The executor measures, on the `e2e/hel1579-pipeline-spine-layout.spec.ts` fixture (it seeds a "Compute column" step; `stepNarrowing.ts` labels the compute kind "Compute column"), via `scrollWidth`/`clientWidth` of `.spine-row__title` (no hard-coded pixel expectations; fonts are the committed local copy), the visible title width for the seeded "Compute column"-class labels at 1100px, list default and max, before and after, and records it in the evidence. Whatever remains truncated is accepted: it is above HEL-1608's ~60px floor, the full label is in the row's accessible name, and the only remaining levers are (a) raising the compaction threshold, which would compact rows at widths HEL-1608 deliberately kept one-line, or (b) shortening step labels, which is a product/copy call. Neither is taken. If the owner wants (a) or (b), that is a follow-up, not this ticket.

## Risks / Trade-offs

- [The selected compact row's summary ellipsizes ~24–28px earlier] → this is the line HEL-1608 already designated to shed width first; the count and title keep theirs.
- [Coarse pointer trigger is 28px with a 44px expander; the expander may overlap neighbouring rows] → the expander is the shared ActionsMenu behaviour, already present on cards and the regular selected row; not changed here.
- [`:has()` support] → Chromium, Firefox and WebKit current versions support it; the e2e matrix covers the shipped browsers. If any project browser lacks it, use a TSX modifier class instead (D3 allows either).
- [Hover-gating guard] → all new hover selectors stay in the allowlisted compact unit or are gated; guard re-run.
