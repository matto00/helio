# HEL-1575 UI decisions (frontend phase B)

- **Changed-dot token: `--app-text` (a neutral foreground). Revised after evaluation 1.** The first choice, `--app-warning`, was wrongly claimed to differ from the accent in every preset: with the Yellow preset in dark mode it is the same amber as the accent (`#f5b944` against `#eab308`). An intent colour can always land on some accent preset, so the dot is the primary text colour, which no accent preset equals in either theme. A neutral 6px dot still reads as a marker on the muted inactive tab. Checked at 1280 in dark and light with the default and the Yellow accent (`evidence/screenshots/cycle2/`). The B2 mockup draws it in the accent; that is a deliberate deviation.
- **Bar mount approach: a new grid row, not a wrapper.** `AppShell` renders `DashboardTabBar` as the first child of the content column when `!isPhoneShell && onDashboardView`, and adds `app-shell--tabs`, which switches the grid to `auto auto minmax(0,1fr)` and moves the command bar to row 2 and `.app-body` to row 3. The rail and context list now span `grid-row: 1 / -1` (was `1 / span 2`) so they cover any row count. The phone override is untouched because the bar never renders there.
- **`CommandPaletteProvider` moved up** to wrap the whole shell (it wrapped only the palette cluster after the grid), because the tab bar's "+" and the box call `useCommandPalette`.
- **Tabpanel.** A `div.app-tabpanel` (`display: contents`, no layout box) wraps the routed `<Outlet/>` always; it carries `role="tabpanel"`, `id` and `aria-labelledby` the active tab only when the bar shows and a tab is active. Always rendering it avoids remounting the page when the bar toggles.
- **Breadcrumb / h1.** `CommandBar` gets `hideDashboardBreadcrumb`; the section name stays, the dashboard name drops. The sr-only `<h1>` is unchanged.
- **Sizes.** Tab height `--control-lg` (40px), bar padding-top `--space-2` (48px total); "+" is the shared `IconButton` (28px, with its own touch expander); the close glyph box is 20px (28px, `--control-sm`, under `pointer: coarse`); tabs are 44px high under `pointer: coarse` (the tab is the bar's geometry, like BottomNav). Tab max width 240px, name ellipsised. Strip scrolls sideways (thin native scrollbar).
- **Known limit.** The close control is a pointer-only affordance with no 44px expander (an expander would overlap the neighbouring tab); its keyboard path is Delete/Backspace, per the APG deletable-tabs pattern (design D8).
- **Active mark.** A 2px `--app-accent` bar on the tab's top edge via `::after` (not a `box-shadow`, which the elevation token guard forbids as a literal). The active tab is raised to `--app-surface` to join the command bar; the bar itself is `--app-surface-soft`.
- **Drop indicator.** 2px `--app-accent-mid` bar on the hovered tab's near half-edge (the documented drop-target idiom), `opacity: 0.5` on the dragged tab. Static.
- **Palette box.** A button (not an input), `flex: 0 0 280px`, `--control-md` high, `--app-surface-soft` well. It collapses to icon + shortcut when the tab bar's container (`container-type: inline-size`) is narrower than **560px** (label hidden by CSS; the accessible name "Search, jump, or ask" never changes). Shortcut caps come from `formatCombo` of the `command-palette` declaration; `aria-keyshortcuts` is `Meta+K` on macOS, `Control+K` elsewhere.
- **Open-tab mode** lists dashboards without the per-kind cap of search (it is a picker); non-empty queries rank with the existing `titleMatchRank` tiers. The coverage caveat is hidden in that mode.
- **No motion tokens added; tab open/close/slide is static** (C6). The CSS file-count guards (elevation, motion) moved 135 to 137 for the two new stylesheets.
- **Checked live (1280 and 375, dark and light, dev account):** five tabs (Ctrl-click opened four), overflow clipping the strip, the box, the palette with the Ask section last; no tab bar at 375. Full screenshots and e2e are phase C.

## Cycle 2 (evaluation 1 change requests)

- **Focus ring.** The tab button fills the strip's height and the strip clips (`overflow`), so the ring would be cut; the tab button's `:focus-visible` uses `outline-offset: -2px` (DESIGN.md section 8). Checked live in both themes: the ring is closed on all four sides.
- **Close control size and touch floor.** The close is 24px (the dense-row mini icon-button size, section 3) for fine pointers. Under `(pointer: coarse)` it is the 28px `--control-sm` box with the canonical `::after` 44px expander (`tapTarget.css` pattern), asserted by `expectTapExpander()`. The expander extends (44 - 28) / 2 = 8px per side, exactly the close's 8px right margin, so it tiles against the next tab; with a 24px box it extended 10px and captured 2px of the next tab (found in evaluation 2, guarded now by a CSS-source test that `(44 - size) / 2 <= margin-right`, resolved from the token values). The earlier claim that a 24px expander "ends at its own tab's right edge" was wrong. Keyboard and assistive-technology close is still Delete.
- **Roving tab stop.** When focus leaves the tablist the tab stop returns to the active tab (APG).
- **Cost of `expireTab`, for the PR.** Expiring a tab invalidates its Outputs' held rows, so an Output shared with another still-warm tab loses row reuse there too and that tab refetches its rows on return. Safe (nothing stale is shown), at the price of one extra rows read per shared Output.

## Final gate round 1

- **Hairline under the active tab removed.** The strip reaches 1px into the bar's bottom border (`margin-bottom: -1px`) and the active tab is 1px taller (`padding-top: 1px` keeps its label on the inactive tabs' baseline), so the raised surface covers the line and joins the command bar as on the B2 board. The bar's height is unchanged. Checked live in dark at 3x.
- **DESIGN.md section 9 close size corrected:** 24px for a fine pointer, 28px (`--control-sm`) for a coarse pointer, with the 44px expander.
