### Non-blocking notes

- **`audit` default argument on the optional tail moves.** `audit` has a default `metadata = JsObject.empty`, and a default does not survive being passed as a function value. The required moves (`panel.batch_update` and `panel.batch_create`) pass metadata explicitly, so they are fine. If the executor also takes D3's optional create/delete tails, `audit("panel.create", ...)` and `audit("panel.delete", ...)` (lines 239 and 370) currently rely on the default. Either the module calls with an explicit `JsObject.empty` (under D4's "audit plumbing" allowance, listed in move-evidence.md) or the module gets a local wrapper with the same default. A missing argument fails to compile, so the risk is a confused executor, not a silent change.
- **When D8 may be invoked is slightly ambiguous.** "after every D3 move" should be read to include the optional `create`/`delete`/`duplicate` tail moves. A D8 floor recorded without those moves is not a floor. The final gate should check that the recorded floor accounts for them.
- **README:** the Holds list in `services/panels/README.md:8-17` needs each new module named (task 2.8). It also currently says "`PanelService`" as a whole. Keep the prose in sync with the CS4 ACL strategy, which still lives in PanelService's class doc.
- **Final gate:** check D7(c) by running the guard functions' logic on the new tree, not by grepping only `PanelService.scala`. The scan covers every main `.scala` file, so a stray `ServiceError.Forbidden(` in a new module is what would break the pinned count.
