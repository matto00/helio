1. BLOCKING, missed second defect: the plan's fix would still 500. PatchSetPreviewProjection.computeAfter (PatchSetPreviewProjection.scala:71-116) matches on `ResolvedAction` (sealed trait, PatchSetApplyTypes.scala:35) and has NO case for ResolvedAction.OutputUpdate / OutputDelete (PatchSetApplyTypes.scala:67-68) and no wildcard (grep for `case _` in the file: none). Add a task + design decision: projection cases for OutputUpdate (after = prior output response with name/config patch applied, like panelUpdateAfter/pipelineRenameAfter, using UpdateOutputRequest(name, config) incl. its validation parity with OutputService.update) and OutputDelete (after = None); decide Impact hints (PatchSetPreviewImpact falls to `case _` => empty; state whether output delete should carry a hint, e.g. bound panels). 2. Silent null-guard parity bug unnamed: PatchSetApplyResolvers.scala:673 `if (ctx.outputRepo == null) ... "boundOutputs" -> JsArray()` in buildPipelineStepDeletePriorState. In preview today outputRepo is always null, so a pipelineStep delete preview silently reports priorState without boundOutputs (not an NPE, no 500) while apply reports them. Wiring fixes it, but the plan must call it out explicitly and add a test (preview of pipelineStep delete with a bound Output shows boundOutputs equal to apply's), since the audit wording ("fix or typed rejection of NPE") would not catch non-throwing degradations. Audit method should be: grep every `ctx.<field> == null` / Option(ctx...) guard, not just dereferences.
3. Null still reachable in production: ApiRoutes wires `outputRepoOpt.orNull` (ApiRoutes.scala:240), null when dbContext is null. Removing the `= null` default (design D2) only forces callers to pass an argument; `.orNull` re-introduces null, so the "compile error" claim in proposal is overstated and a no-DbContext fixture previewing an output edit still NPEs. Decide: typed ServiceError (e.g. BadRequest/unsupported) when ctx.outputRepo is null in resolveOutputUpdate/Delete (fixing apply too), or state it is unreachable. Also PatchSetApplyService's own constructor param keeps `outputRepo = null` (PatchSetApplyService.scala:66) — say whether it stays (then apply can still silently omit it, and the parity test must construct apply via the same path).
