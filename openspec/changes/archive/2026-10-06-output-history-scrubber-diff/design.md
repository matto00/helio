## Context

L1–L6 store a per-Output summary on every real run (`output_snapshot_history`), optionally a node payload (`node_payload_history`, ≤1000 rows/≤1 MiB, skip-over-cap), and expose `GET /api/outputs/:id/history` (points newest-first with `id`/`hasPayload`, `limit` 1..100 default 30), `GET /api/outputs/:id/history/:pointId/rows` (authenticated only) and the public summary-only panel variant. L5 rendered metric delta/sparkline on dashboards via `features/panels/history/*` (`useOutputHistory`, a module cache keyed `output:<id>` / `public:<d>:<p>`, `configCompare`, `compareLabel`, `FILTERED_NOTE`).

Owner rulings for this ticket (2026-10-06, escalation `HEL-1277-1791271966819-f692da`): Q1=A per-Output History view from each Output card; Q2=A whole-row multiset diff, highlight new-or-changed + "no longer present" count, no cell-level; Q3=A compare to the next-older retained point labelled by capture time, never "previous run"; Q4=B dashboard chart panels with `config.compare` draw the baseline summary series as a labelled "vs" overlay, hidden under a viewer filter; changed-rows stays scrubber-only.

Verified facts this design depends on (main 3962e6eb2):
- `OutputGalleryCard` is a single `<button>` (`aria-label="Open {name} output"`); no secondary action, so a sibling action requires a wrapper.
- `usePipelineDetailPage.ts:661` `handleOpenOutput` → `OutputEditorSheet` (a `Modal`). `RunHistoryModal` is a separate precedent.
- Chart path: `PanelContent` → `ChartRenderer` → `ChartPanel` → `useChartOption` (useMemo) → `buildChartOption`. Dashboard output panels load rows in pages of 200 (`usePanelData.ts:160,187`).
- `filterActive` for a panel is computed in `PanelContent.tsx:313` (viewer filter || server cross-filter || cross-filtered).
- The history response's `baseline` is `{capturedAt,rowCount,value}` — no series; a 7d/30d baseline is usually older than the newest 30 (or 100) points on a frequently-run pipeline (D4 keeps ≤288 points/day in the last 24h).
- `DataGrid` rows are `<tr key={i}>` with no per-row class hook; `TableRenderer` writes sort/filter/format state back via `updateOutput` only when `ownerId`/`canWrite` permits.
- No shared Slider/Tooltip primitive; native `<input type="range">` is the in-repo pattern.

## Goals / Non-Goals

**Goals:** AC1 scrubbing shows each point's summary, and its rows when a payload exists; AC2 overlay series is labelled; AC3 light/dark checks. Plus the driver constraints in ticket.md.

**Non-Goals:** a chart Compare picker in the Output editor (D12; follow-up noted for the driver); `historyPayloads` toggle UI/MCP (HEL-1331); "previous" semantics after thinning (HEL-1285); changed-rows on dashboards (Q4); a key-column diff (Q2-C); any migration; RunHistoryModal layout/behaviour changes (its only change is routing trigger labels through the shared helper, so an `auto-run` run now reads "Auto-run" instead of an empty badge — a deliberate small fix; it reuses the neutral trigger style, no new modifier); provenance popover changes; replacing a dashboard chart's primary data with server summaries.

## Decisions

**D1 Entry point (Q1).** `OutputGalleryCard` becomes `<div class="output-gallery-card">` wrapping the existing open `<button>` (unchanged aria-label/behaviour, so existing tests keep their selector) and a sibling footer button "History" (`aria-label="History for {name}"`, lucide `History` icon + text, ghost style via existing button tokens, `tap-expand-44`). `OutputsGalleryTab` gains `onOpenHistory(output)`; `usePipelineDetailPage` holds `historyOutput: Output | null`; `PipelineDetailPage` renders `<OutputHistoryModal>` (shared `Modal`, `size="xl"`, title "{name} — history"). The Outputs rail is not changed.

**D2 History fetch is the History view's own, not the shared cache.** The view fetches `GET /api/outputs/:id/history?limit=100` through a new `fetchOutputHistory(outputId, {limit})` option. It does NOT write into `outputHistoryCache` (that cache feeds dashboard metric sparklines from the default 30-point read; a 100-point entry would change them). When exactly 100 points return, the view shows a muted "Showing the newest 100 recorded runs" note. Loading → `Spinner`/`Skeleton`; error → `InlineError`-style intent-error text; zero points → `EmptyState` ("No runs recorded for this Output yet" — copy avoids "previous").

**D3 Types.** `HistoryPoint` gains optional `id?: string`, `hasPayload?: boolean` (absent on the public variant) and a typed `summary.series?: HistorySeries | null` where `HistorySeries = {mode:"grouped"|"rows"; x:string; y:string; agg:string|null; points:[unknown, number|null][]; totalPoints:number; downsampled:boolean}`; summary `columns?: Record<string,{count,sum,min,max}>`. `HistoryResolvedPoint` gains `series?: HistorySeries | null`. New `fetchHistoryPointRows(outputId, pointId) → {rows: Record<string,unknown>[]; rowCount}`.

**D4 Scrubber.** A native `<input type="range">` (min 0 = oldest … max n-1 = newest, default newest) styled from the existing slider recipe tokens, with `aria-valuetext` = localized capture time + "N rows" (a single control; no separate tick strip). Prev/next `IconButton`s ("Older run", "Newer run") flank it for pointer users. Selected-point header: capture time, trigger source label from a shared `triggerSourceLabel(s: string)` helper extracted from RunHistoryModal's map and extended: manual→Manual, scheduled→Scheduled, external→External, auto-run→Auto-run (HEL-1093 dataset-write runs, which record history per D5), any other string→the raw value sentence-cased (never `undefined`); RunHistoryModal keeps its current rendering via the same helper, row count. Comparison caption: "vs <localized capture time>" for the next-older point (Q3); none for the oldest.

**D5 Body by kind.** Summary block for every kind: row count, headline metric (`summary.metric.value` formatted with the Output's `format` when present, with the comparison point's value beside it as "vs <time>: <value>"), and a per-numeric-column stats `DataGrid variant="preview"` (column, count, sum, min, max) when `summary.columns` is non-empty. Chart Outputs (`kind==="chart"`, non-null `summary.series`): a chart rendered through the existing `ChartRenderer` from the series (rawRows = points as strings, headers `[x, y]`, fieldMapping `{xAxis:x, yAxis:y}`, `chartType` from `readChartConfig(output.config)` and appearance following the `OutputPreviewPane` precedent `{...defaultPanelAppearance, chart: {...defaultChartAppearance, chartType}}` — appearance belongs to panels, not Outputs) with the overlay from D8, gated by a pure `selectPointOverlay(selected, comparison)` helper (beside `selectChartOverlay`): overlay only when the comparison series is non-null, has identical `mode`/`x`/`y`/`agg` to the selected series, and in `rows` mode neither side repeats an x; downsampled series are allowed here (both sides share the reducer's 200-point cap, unlike D9's 200-row dashboard primary, which is why D9 rejects them). Series points whose y is null are omitted from the primary rows (never coerced to 0 by `parseFloat("")`). The view does not refresh on pipeline-terminal events while open (a re-open refetches); stated, not a defect. Rows section for every kind: when `hasPayload`, payload rows in `TableRenderer` (records via `paginationRows`, no `ownerId` → read-only, no write-back), all stored columns (payload is the node's rows, not the Output's projection — stated in a caption "All columns stored for this run"); else the note "Rows weren't stored for this run — summary only."

**D6 Payload loading.** On selection, fetch the selected point's rows (if `hasPayload`) and its comparison point's rows (if it exists and `hasPayload`), via a per-modal `Map<pointId, Promise>` memo so scrubbing back is free; responses for a no-longer-selected point are ignored (selection-id guard). A failed payload fetch shows intent-error text in the rows section and disables the diff for that pair (never "removed").

**D7 Diff (Q2).** Pure `diffRows(selected, comparison)`: canonical key = `JSON.stringify` of the row with keys sorted recursively (so key order is irrelevant; `1` vs `"1"` differ — stored JSON types are authoritative). Build a count map from comparison; walk selected rows, consuming a match → unchanged, else changed. Returns `{changed: Set<object>, noLongerPresent: number}` keyed by row OBJECT identity (rows survive TableRenderer's sort/filter as the same objects; verified by a test with an active sort). Rendering: `DataGrid` gains optional `rowClassName?(row) → string|undefined`; `TableRenderer` passes it through; `TableRenderer` gains `leadingColumns?: ColumnDef[]`, rendered before the key-derived columns via `ColumnDef.render(row)` and EXCLUDED from filtering, sorting, pinning, `columnOrder`, width and every persistence path (rows are never mutated, so object identity holds). The history view supplies one leading "Change" column whose cell reads "New or changed" for flagged rows (text cue, not colour alone; row tint uses an accent wash appropriate to the modal surface per DESIGN.md HEL-866 rules, both themes). Count line: "N rows from <time> no longer present" (0 → omitted). Only when both points have loaded payloads; otherwise "Row comparison unavailable — rows weren't stored for one of these runs." (or nothing when there is no comparison point).

**D8 Overlay in `buildChartOption` (AC2).** New param `overlay?: {label: string; points: [unknown, number|null][]} | null`. Applied after `applyChartTypeOptions` and before `applyAxisTriggerTooltip`/`applyHoverEmphasis` (so tooltip/legend see it), only when chartType is `line`|`bar`, the built option has a category `xAxis` and exactly one series, AND the bar options are not `stacking: "normalized"` (the primary has become percent shares on a `max:100` axis) and not `orientation: "horizontal"` (category axis moved to yAxis). Each of these omissions is explicit in the spec and unit-tested. Data = primary categories mapped by `String(x)` equality to overlay values (first occurrence), missing → `null`; if no category matches, no overlay. Series: `name: label`, no `stack`, `z` below primary, line → `lineStyle.type:"dashed"`, `symbol:"none"`; bar → `itemStyle.opacity: 0.45`; colour = new `ChartThemeTokens.textMuted` (`--app-text-muted`, resolved in `resolveChartTheme`) so parity holds in both themes; legend shown (respecting existing compact/legend-hide rules — in compact mode the legend is hidden, so the overlay series name still appears in the axis tooltip). Pure function; unit-tested.

**D9 Dashboard chart overlay (Q4).** In `PanelContent`'s chart branch: `compare = configCompare(output.config)`; `useOutputHistory(..., enabled = compare !== null, compare)` (shared cache/key with metric panels — same response). `selectChartOverlay(history, chartConfig, {filterActive, rowsTruncated})` returns `{label: "vs " + compareLabel(compare), points}` or null, omitting when: compare null; history/baseline null; `baseline.series` null or `downsampled`; series identity ≠ what the DASHBOARD actually plots — dashboard chart panels ignore `config.aggregation` (`usePanelData` sets `chartAggregate: null`; `PanelContent` plots rows mode `fieldMapping.xAxis` by `fieldMapping.yAxis`), so the rule is: overlay only when `baseline.series.mode === "rows"` and `series.x === fieldMapping.xAxis` and `series.y === fieldMapping.yAxis`; a chart Output with `config.aggregation` set gets NO dashboard overlay (its stored series is `grouped`, which the panel does not plot). Found issue, recorded not fixed: the editor preview (`OutputPreviewPane.tsx:87`) groups while dashboards don't; `filterActive`; `!rowsComplete` — authenticated surfaces: the existing `rowsTruncated` prop (from `usePanelData`'s `paginationEntry.hasMore`; already passed by PanelCard, PanelFullscreenOverlay, PanelDetailModal); public dashboards: `usePublicPanelData` gains a returned `rowsTruncated = total > loadedRowCount` (it loads one 200-row page and already tracks `total`) and `PublicDashboardViewerPage` passes it to `PanelContent` (file outside the ticket's Touches list, required for correctness). `rowsTruncated === undefined` is treated as NOT complete inside `selectChartOverlay` (fail closed: no overlay when completeness is unknown), so a future call site that forgets the prop omits the overlay instead of drawing a misleading one; rows mode with a repeated x on either side. The hook lives in a new child `ChartOutputPanel` component rendered by the chart branch (after `OutputPanelContent`'s loading early-return, mirroring `MetricOutputPanel`), never inline. Label: `"vs " + compareLabel(compare)` (`vs 7d`, `vs previous`), except when `compareLabel` would return the generic `"custom"`, where the label is `"vs " + <localized baseline capture date>`. Threaded `ChartOutputPanel → ChartRenderer → ChartPanel → useChartOption` (added to its memo deps) → `buildChartOption`. Public dashboards use the existing `historySource` (summary only; the payload route is never called from dashboards).

**D10 Backend: `series` on resolved points.** `ResolvedHistoryPoint` gains `series: Option[JsValue]` from `summary.fields("series")`, serialized as `series` (JSON null when absent) on `current`/`baseline` in both authenticated and public responses. No new query (the point is already loaded); the HEL-1273 statement-count spec stays green unchanged. Additive to the wire contract; public allow-list test extended. Contract files updated in the same change: `schemas/outputs/output-history-response.schema.json` and `schemas/outputs/public-output-history-response.schema.json` `resolvedPoint` gain REQUIRED `series: oneOf [null, #/$defs/seriesSummary]` (reusing/adding the series def), keeping `additionalProperties:false`; the three schema-seam route specs (OutputHistoryRoutesSpec, OutputHistoryPayloadRoutesSpec, OutputHistoryPublicRoutesSpec) validate it. Note: parked HEL-1326 will add `metric` identity to the same objects — an additive sibling field, trivial merge.

**D11 MCP (`get_output_history`).** Option (a): `getOutputHistoryHandler` strips `current.series`/`baseline.series` unless `includeSummaries` is true, exactly as it already strips `points[].summary` (same bulk rationale, ≤2×200 points). `helio-mcp/src/types.ts` `OutputHistoryResolvedPoint` mirror gains `series?`; handler test covers both modes. No tool-schema/description change beyond noting `includeSummaries` also governs resolved-point series.

**D12 Chart `compare` reachability (non-goal, stated).** The Compare picker is metric-only (`OutputEditorSheet.tsx:548-561`) and `buildOutputConfig`'s chart branch never writes `compare`, so the Q4=B dashboard overlay is reachable today only by API/MCP PATCH of `config.compare` on a chart Output. A chart Compare picker is outside this ticket's Touches and is NOT built here; it is recorded as a follow-up (noted, not filed — driver files). The overlay itself, the History view (which needs no `compare`), and all tests are unaffected. The driver is told explicitly in the final report.

**D13 e2e payload tier.** Payloads need tier beta/owner (free cap 0). The e2e spec registers a fresh user, then sets ONLY that user's tier via a new `e2e/support/historySeed.ts` helper `setUserTierForTest(userId, "beta")` (psql, `UPDATE users SET tier=$tier WHERE id=$exact_id`, asserting exactly 1 row; never by email/pattern; never matt@helio.dev), and records the user id and every created resource id in the spec's teardown log. Payload opt-in via `PATCH /api/outputs/:id` `config.historyPayloads: true` (no UI toggle, HEL-1331). No `ci.yml`/`playwright.config.ts` change.

## Risks / Trade-offs

- [Dashboard overlay rarely shows for >200-row charts] → by design (`rowsComplete`): comparing first-200-rows vs all-rows would mislead. Follow-up candidate, not filed: render chart panels from the server series when complete (D3-analogue for charts).
- [Payload = node rows, not Output projection] → caption + all columns shown, so a highlight never hinges on a hidden column.
- [Multiset diff marks a one-cell edit as "new or changed" plus one "no longer present"] → accepted per Q2=A.
- [`limit=100` cap on the scrubber] → stated in UI; older points remain reachable via API.
- [Modal hover/selected tint contrast] → evaluator measures both themes on the running app.
