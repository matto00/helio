### Change Requests
1. tasks.md 1.2 (and proposal "Impact" "new e2e spec", task 4.1) name `frontend/e2e/hel1007-multi-root-reorder.spec.ts`; that directory does not exist. Playwright's testDir is repo-root `./e2e`. Correct the path to `e2e/hel1007-multi-root-reorder.spec.ts` (a spec at the stated path would never run, making the "red on main / green after" evidence vacuous).
2. Decision 4 (focus): specify that `pendingFocus` is cleared when consumed AND when the reorder produces no commit (handleReorderSteps early-returns on `!id`, or the CR2 refusal path, or index guards), and that the effect fires only for the commit caused by that reorder. As written ("effect keyed on a pendingFocus ref"), a stale pendingFocus can steal focus on a later, unrelated laneGraph change (e.g. typing in a step editor). Also state how the effect finds the button (e.g. data-step-id attribute on the card/button), since StepCard is memo'd and refs don't cross it, and add a test for the no-op/stale case.
3. Decisions 1/2: enumerate the remaining root-0-relative sites the executor must make lane-scoped: drop-indicator render (`draggedIndex !== null && overIndex === idx`), per-card `onDragOver/onDrop` wrapper (needs adding to LaneColumn's step-section for reorderable lanes), real `stepIndex` instead of `-1` for reorderable lanes, and the `idx>0 ? handleMoveUp : undefined` / `idx<len-1 ? handleMoveDown : undefined` edge-disabling for lane-column cards. Also state the one-step root trunk lane expectation (both buttons disabled, not hidden; RootColumn passes isCompact=false) and that drops are ignored when over-lane != dragged lane.
4. Decision 2's "no existing test depends on disabled controls" sweep must include the e2e suite, not only jest: e2e/hel908-step-card-split.spec.ts and e2e/hel908-trunk-reorder-order.spec.ts query "Move step" and will be affected by the renamed aria-label (Decision 3). Add a task to update and re-run them (they are not covered by `npm test`).
5. Decision 3 naming: two roots can plausibly share a `dataSourceName`, and every card in a lane gets the identical label. Either append disambiguation (lane position/root index, or the step name) or explicitly record that the label is lane-level only and ambiguity between same-named sources is accepted, with the spec scenario "each lane's controls name that root's source" tested using distinct names.
