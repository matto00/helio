### Change Requests
1. D5 leaves `hasPendingLayout` stuck true in a realistic path. Scenario: drag, flush (PATCH in flight), panel create lands (store layout = drag + placement, != sentLayout), PATCH response arrives. Reducer keeps local layout and leaves pending as is; `.then` sets baseline = server layout, and per tasks 3.2 only "re-asserts pending when latestLayoutRef differs". If the server layout already equals the local layout (create finished server-side before the PATCH was processed), nothing ever clears pending: SaveStateIndicator shows dirty forever, `layoutPendingDispatchedRef` stays true so a later real edit does not re-dispatch, and persistLayout no-ops on the equality guard. Same for undo-to-previous-baseline equal to server result. Revise D5/task 3.2: after the response, set pending = (latestLayoutRef !== new baseline) in BOTH directions (dispatch false when equal) and keep `layoutPendingDispatchedRef` in sync; the reducer's keep-branch should not leave a stale true. Add a test for the equal-to-server case.
2. AC5 is under-covered. Canonical specs other than the two in the delta still state a 250 ms layout debounce: `openspec/specs/panel-drag-perf/spec.md:20,26` ("250ms debounced layout-persistence write", "within the debounce window (250ms after drag stop)") and `openspec/specs/write-path-audit/spec.md:48,62,79,184` (also references nonexistent `PanelGrid.tsx` debounce). Neither the proposal's Modified Capabilities, spec deltas, nor tasks touch them. Add deltas (or tasks) for panel-drag-perf and write-path-audit and a task verifying `grep -rn "250" openspec/specs` shows no layout-debounce claim.
3. The canonical `openspec/specs/frontend-layout-persistence/spec.md` Purpose is already hand-edited in the worktree (uncommitted diff) outside the delta. State in tasks that this edit is intentional and is retained at archive (or fold it into the delta workflow), so archive/spec-sync does not clobber or duplicate it; verify openspec hygiene check passes with it.
4. Spec ambiguity: scenario "Undo marks the layout pending without an immediate PATCH" says "no layout PATCH has been sent" after a Save now PATCH in the same scenario. Reword to "no further layout PATCH has been sent since the undo". Also the "A traversal that changed nothing" scenario should say the undo target is the same layout (reference-equal) so it is testable as written.
