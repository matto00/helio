### Test-coverage-gap investigation finding (task 3a.2)

Root cause confirmed by reading `PipelineCycleDetectionServiceSpec.scala`'s `addStep`/`updateStep`/`duplicateStep` "API-level" describe blocks directly: this is category (b), not (a). The right write paths WERE exercised with a config that closes a real cycle — but every assertion is the untyped `result shouldBe a[Left[_, _]]`, which `Left(ServiceError.InternalError(...))` (the actual pre-fix return value) satisfies exactly as well as `Left(ServiceError.BadRequest(...))` would, so the 500 never failed a test. A second, compounding factor: despite their "(API-level)" section-comment label, these tests call `service.addStep`/`service.updateStep`/`service.duplicateStep` directly (service-level) rather than through a real Pekko HTTP route, so even a type-pinned assertion there would not have proven the route's `ServiceError -> HTTP status` mapping actually fires. `PipelineCycleRouteStatusSpec.scala` (added this cycle) closes both gaps at once.
