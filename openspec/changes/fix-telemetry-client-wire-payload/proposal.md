## Why

Every client product event batch is rejected with 400 because the wire payload carries the client-only `userId` field, which the server's allow-list validator rejects. No client telemetry has ever been stored. HEL-1208 passed its gates because client and server were each tested against their own idea of the contract.

## What Changes

- `track.ts` serializes a wire event (`event`, `properties`, `occurredAt`) that excludes `userId`; `userId` stays on the queued record for the per-user guard.
- A shared fixture of the client's real wire payload is generated by the client serializer test (and compared against the committed file) and validated by the backend `ProductEventRegistrySpec` through the real `validateClientEvent`, so contract drift on either side fails a test.
- A 400 response is logged once (with the server's message) via a distinct error log, and drops the batch: an identical payload can never succeed. Previously queued legacy items (which still contain `userId` in localStorage) are stripped at send time, so they are accepted after the fix.
