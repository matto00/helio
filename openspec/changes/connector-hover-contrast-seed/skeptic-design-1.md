### Change Requests

1. **D3 "Test connection" selector regresses the Edit modal.** D3/task 2.2 target `.connectors-page__btn--secondary` (also implied by "Secondary recipe" on the class). That class is also "Replace credential" in `EditConnectorModal.tsx:115`, which renders in-tree inside `.connectors-page` on `--app-surface-strong`. In light theme `--app-surface-raised` and `--app-surface-strong` are both `#ffffff` (A.2), so that hover would go to 1.00. This is the exact cycle-1 regression A.2 warns about, and no guard cell opens the Edit modal, so nothing would catch it. Revise D3 and task 2.2 to scope the raised hover to the row context, for example `.connectors-page__row-actions .connectors-page__btn--secondary:hover:not(:disabled)`, and say explicitly that modal-hosted `.connectors-page__btn`/`--secondary` keep `--app-surface-soft`. Use the same row-actions scope for the actions-trigger override (in place of bare `.connectors-page .actions-menu__trigger`) so both fixes are keyed to the backdrop they were measured on. Add a task to check the Edit modal's "Replace credential" hover after the fix, using a bearer/api_key connector so `canRotate` is true. A visual check or a probe is enough.
2. **D1's "no `CONNECTOR_MASTER_KEY` is needed" is false.** `ConnectorRepository.create` (l.60-69) always calls `ConnectorCredentialRepository.create`. That calls `secretBackend.encrypt(plaintext)` even for `""` (ConnectorCredentialRepository.scala:33-48), and it fails with `MasterKeyError.NoKeyConfigured` when no key is set. Correct D1: the seed requires the backend to have a master key. CI's `e2e` and `e2e-prod-build` jobs set a fixed test value (ci.yml:677-678, 829-830), and existing rest_api-creating specs already depend on it. State that a local seed POST failing on encryption is an environmental BLOCKER to report. It must not be worked around, and the executor must not read or print any `.env` (C1).
3. **The spec's "row and trigger are among the sampled controls" has no mechanical enforcement at 1440.** The 1440 route cells sample evenly once a view exceeds `MAX_ELEMENTS_PER_VIEW = 24` and have no `fullySampled` check. A later header or sort control could then sample the connector controls out while the partition check still passes, which is the same silent blindness this ticket exists to close. Add a task and design line: in every `/connectors` cell (1440 and narrow), assert that the seeded row's doc id, its actions trigger's doc id, and the "Test connection" button's doc id (where mounted) are in the covered set. Follow the HEL-1649 refresh-button precedent (narrow.ts:139-150). Alternatively, apply `fullySampled` to the 1440 `/connectors` main view. Log the result per cell.
